# Two-offer service candidate

This is a source-only, unactivated candidate. Apply its explicit component
overlay to the recorded parent. Runtime manifests are inventories; no binaries,
configured deployments, credentials, records, sealed packets or wallet data are
redistributed here. Existing source snapshots remain unchanged.

The launcher retains the exact original sealed backend/resources and explicitly
admits a second fixed offer. Both publication scopes use one original journal,
nonce and cumulative spending allowance. Refund targets use one existing ledger
and one global count/execution limit. The authenticated refund-context upgrade
requires an independently finalized matching new vault, authenticates every old
row and preserves counters, jobs, first signatures and raw transactions under a
single managed-head compare-and-swap. An uncertain reply does not reset state.

The four new test modules and their static Python fixture closure are included
in this directory. They require the existing pinned local EVM/native build
tools and offline AWS SDK inputs from the broader release. Tests use synthetic
private data; the larger 70-test integration result additionally includes the
existing backend/server/refund regression suites. EC2 checks mounted no sealed
packets or credentials and changed no production services. Policy simulation
is read-only and is not a complete effective-access or real role-call proof.

The additional reserve, finite record permissions, refund-context authority and
service/client configuration require exact fresh owner review before activation.
No owner payment/import/redemption, independent Ubuntu workflow, full protected
recovery, antirollback or independent security/build acceptance is claimed.
