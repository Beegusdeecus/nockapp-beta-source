# Index-first delivery and one-call checkout

The source overlays retain their exact older runtime parents; apply only the listed source replacements. Runtime manifests are inventories, not redistributed binaries or configured installations.

Index-first publication saves exact signed bytes locally, durably admits one original ticket, finalizes the immutable commitment, then verifies and conditionally delivers those same bytes. Local reconciliation covers all approved unfinished operations plus the latest five completed ones. It checks individual hashes with bounded work/backoff, never uploads unsent drafts, never signs again or allocates another ticket for repair. Content delivery and canonical inclusion are separate. Corrupt public objects are repaired only through versioned, ETag-conditional writes and checked readback. Network failure is not evidence of absence.

One-call checkout is an incompatible new public offer/contract domain. Old blinded inputs, journals, purchases, tickets and assigned history remain pinned to their old scope. A new contract address and exact refund/service configuration require separate reviewed owner actions before this offer can activate. The old armed payment remains preserved; current nonpayment is not terminal evidence. No permission, authority or budget increase is part of index-first deployment.

Tests use synthetic private data and local EVM/storage/finality fixtures except the stated empty-private-mount public reads. These do not establish fresh-wallet, full Ubuntu, protected recovery, anonymity or production-security acceptance.
